# A: GIMP 3.2.8 architecture (source study)

**Sources:** gimp `GIMP_3_2_8` @7addd2b, gegl 0.4.72 @02096df, babl 0.1.128 @4abcea4.
**Paths** are given relative to each repo root and prefixed `gimp:`, `gegl:` or `babl:`. Line numbers refer to these commits.
**Tags:** **[C]** means confirmed by reading the source. **[I]** means inferred and not verified. No performance numbers are claimed.

---

## 1. Languages, frameworks, and the top-level split

**Languages [C]**
- Almost everything is **C on GObject**.
- There are 10 C++ `.cc` files, used for templated hot loops: `gimp:app/gegl/gimp-gegl-loops.cc`, `app/paint/gimppaintcore-loops.cc`, `app/core/gimp-parallel.cc`, `gimpbrush-mipmap.cc`, `gimppickable-contiguous-region.cc`, and others.
- **Perl** is the PDB code generator: `gimp:pdb/pdbgen.pl` plus 60 `pdb/groups/*.pdb` files. Generated files carry the header "auto-generated by pdbgen.pl" (`app/pdb/layer-cmds.c:18`).
- Python 3 (80 `.py`), Scheme (157 `.scm`, Script-Fu on TinyScheme), 3 JS, 3 Lua and 1 Vala file (demo extension).
- The build system is Meson.

**Dependencies [C]** (`gimp:meson.build:441-1110`):
- GLib/GObject/GIO ≥2.70
- **GTK+ 3 ≥3.24.0**
- **GEGL ≥0.4.66**, **babl ≥0.1.118**
- cairo ≥1.14
- pango ≥1.50, harfbuzz, fontconfig, freetype
- lcms2 ≥2.8
- libmypaint ≥1.5 plus mypaint-brushes-2.0
- gexiv2/exiv2, gdk-pixbuf, json-glib, libarchive, appstream, librsvg, gobject-introspection
- Format libraries (libpng, libjpeg, libtiff, webp, heif, jxl, openjpeg, poppler, OpenEXR, …) are used **by plug-ins**.

**Repository split [C]**
- **app/** is built as about 20 static libraries.
  - `gimp:app/meson.build:122-155` separates **console_libapps** (core, file, file-data, gegl, internal-procs/pdb, layer-modes, operations, paint, path, plug-in, text, xcf, config) from **gui_libapps** (actions, dialogs, display, gui, menus, propgui, tools, widgets, plus libgimpwidgets).
  - Two executables are built:
    - **gimp-console**, compiled with `-DGIMP_CONSOLE_COMPILATION`. Its `gimpconsole_deps` contain **no gtk3**.
    - **gimp**, the GUI binary (`app/meson.build:186-216`).
- **libgimpbase/color/config/math/module/thumb**: shared by the core and plug-ins.
- **libgimpwidgets**: GTK widgets shared by the core and plug-ins.
- **libgimp** and **libgimpui**: the plug-in client libraries. The core does **not** link them; `app_libgimps` excludes libgimp.
- **pdb/**: the generator that emits `app/pdb/*-cmds.c` and `libgimp/*_pdb.c`.
- **plug-ins/**: separate executables.
- **modules/**: GModule plug-ins, consisting of 5 display filters, 3 color selectors and 3 controllers (linux-input, DirectInput, MIDI).
- **extensions/**: `.interp` files for gjs and lua, plus the "goat-exercises" demo written in C, gjs, lua, py3 and vala.
- **menus/** (GtkBuilder `.ui` plus XSL), **themes/** (GTK CSS), **etc/** (default `gimprc`, `sessionrc`, `toolrc`, `controllerrc`).
- Caveat: `devel-docs/gimp-module-dependencies.svg` still names 2.x modules (`app/base`, `app/composite`, `paint-funcs`), so it is **stale**.

## 3. Initialization and lifecycle

**main() [C]** (`gimp:app/main.c:671`)
- Handles signals, i18n and option parsing.
- `app_libs_init` (`app/app.c:115`) sets `gegl_config()` `use-opencl=FALSE` and `application-license=GPL3` before GEGL starts. It also adds GEGL's GOption group and, in the GUI build, GTK's group (`gui_libs_init`, `gui/gui.c`).
- `g_option_context_parse_strv` (`main.c:912`) runs GEGL's post-parse hook (`gegl:gegl/gegl-init.c:482,788`). That hook calls `babl_init()` (`:807`) and loads GEGL operation modules (`:892`).

**app_run() [C]** (`app.c:178`)
1. `gimp_new()` creates the root **`Gimp`** object (`:232`).
2. `gimp_console_app_new` or `gimp_app_new` (`:252/256`).
   - **`GimpCoreApp`** is a GInterface (`gimpcoreapp.c:52`).
   - `GimpConsoleApp` extends `GApplication` (`gimpconsoleapp.c:35`).
   - `GimpApp` extends **`GtkApplication`** (`gui/gimpapp.c:56`).
3. User-dir install or migration.
4. `gimp_load_config` (`:289`).
5. `errors_init`.
6. `gimp_gegl_init` (`:312`).
7. `g_application_run` (`:321`) emits "activate", which calls `app_activate_callback` (`:373`):
   - `gui_init()` (`:398`): unique-instance handling, icon themes, `gimp_widgets_init`, DnD, themes, canvas styles and splash. It connects to the Gimp signals (`gui.c:312-325`).
   - `gimp_initialize` (`:408`), which emits **"initialize"**.
   - `gimp_restore` (`:427`), which emits **"restore"**.
   - Crash-recovered XCFs are offered.
   - Command-line files are opened (`:518`).
   - `gimp->initialized = TRUE`.
   - `gimp_batch_run` (`:539`).
8. After the main loop: `gimp_gegl_exit`, unref of Gimp, `gegl_exit` (`:334-342`).

**The Gimp object [C]** (`app/core/gimp.h` `struct _Gimp`, `gimp.c`)
- Holds config and edit_config, the **`GimpGui gui` vtable**, the images container, item/image ID tables, displays, the clipboard, 8 data factories (brush, dynamics, mybrush, pattern, gradient, palette, font, tool_preset), the PDB, the plug-in manager, the extension manager, module DB, tool info, templates, documents, and the default and user `GimpContext`.
- `gimp_init` (`:240`) creates the containers and calls `gimp_data_factories_init`.
- `gimp_constructed` (`:312`) runs modules init, `gimp_paint_init`, creates the extension, plug-in and PDB managers, then `xcf_init`, `file_data_init` and contexts.

**Phases.** The signals are `G_SIGNAL_RUN_LAST` (`gimp.c:159-186`), so handlers run in this order: GUI handler, then class default, then GUI "after" handler. [C]
- **initialize**: `gimp_real_initialize` (`:551`) adds built-in data, `internal_procs_init` (786 procedures, `app/pdb/internal-procs.c:33`), compat procs and `gimp_plug_in_manager_initialize`. After that, `gui_initialize_after_callback` (`gui.c:521`) creates the tools.
- **restore**: `gimp_restore` (`:857`) loads parasiterc, `gimp_data_factories_load`, templates and modules, then emits RESTORE.
  1. `gui_restore_callback` (`gui.c:554`) installs the GUI vtable (`gui_vtable_init`) and calls `actions_init`, `menus_init`, `dialogs_init`, devices, controllers, `session_init`.
  2. `gimp_real_restore` (`:573`) restores plug-ins (`gimp_plug_in_manager_restore`, `plug-in/gimppluginmanager-restore.c:88`). That function searches the plug-in dirs, reads the cached **pluginrc**, queries changed binaries (`-query`), runs `-init`, adds procedures to the PDB, sorts file procedures, runs extensions and pre-builds babl fishes (`gimp_babl_init_fishes`).
  3. `gui_restore_after_callback` (`gui.c:626`) restores the recent list, `menus_restore` (shortcutsrc), devices, controllers and modifiers, then `session_restore`, which opens windows.
  - Because the GUI scaffolding exists before plug-ins register, plug-ins can attach menu entries. [I on rationale]
- Data factories are `GimpDataLoaderFactory` objects with per-extension loaders (`gimp-data-factories.c:66`). Fonts load asynchronously through `GimpAsyncSet`, and `gimp_is_restored` waits on it (`gimp.c` `gimp_is_restored`, `gimpdatafactory.c:627`). [C]
- **exit**: `gimp_exit` (`:914`) emits "exit" using the true-handled accumulator.
  1. `gui_exit_callback` (`gui.c:724`) shows the quit dialog and *cancels* the exit if displays are dirty. Otherwise it saves sessionrc, devicerc, controllerrc, modifiersrc, shortcutsrc (`menus_save`) and tool options.
  2. `gimp_real_exit` (`:590`) shuts down plug-ins, extensions and modules, and saves data factories, templates, parasiterc and unitrc.
  3. `gui_exit_after_callback` tears down the GUI.
  4. `app_exit_after_callback` calls `g_application_quit` (`app.c:583`).

**Config [C].** The class chain is `GimpGeglConfig → GimpCoreConfig → GimpDisplayConfig → GimpGuiConfig → GimpDialogConfig → GimpPluginConfig → GimpRc` (G_DEFINE lines in `app/config/*.c`). It is serialized with libgimpconfig into `gimprc`. `gimp->config` and `edit_config` are kept in sync by notify handlers, and properties flagged RESTART are not applied live (`gimp.c` `gimp_edit_config_notify`). Other rc files include sessionrc, shortcutsrc, toolrc, devicerc, controllerrc, contextrc, templaterc, pluginrc, modulerc, extensionrc, unitrc, parasiterc, profilerc, colorrc, modifiersrc and dockrc.

## 4. UI/engine separation

- **No GTK in the engine [C].** No file in `app/core, paint, gegl, operations, xcf, file, pdb, plug-in, text, path, config` includes `<gtk/gtk.h>`. The only GDK-family header there is `gdk-pixbuf` (10 core files).
  - `libappcore` meson deps are cairo, gegl, gdk_pixbuf, libarchive, libmypaint, gexiv2, appstream, pango and libunwind, with **no gtk3** (`app/core/meson.build:274-291`).
  - `libapppaint` depends only on cairo, gegl, gdk_pixbuf, gexiv2 and libmypaint.
  - 596 files in the GUI dirs include gtk.h.
- **How the core calls "up" [C]:**
  1. **`GimpGui` vtable** (`app/core/gimp-gui.h:23`). It covers ungrab, set/unset_busy, show_message, help, wait, program class, display name, user time, theme and icon dirs, `get_window_strategy`, `get_empty_display`, `display_create/delete`, `displays_reconnect`, `progress_new/free`, PDB data-chooser dialogs, recent list, mount operation, and color-profile and rotation policy queries. Defaults are no-ops (`gimp_gui_init`). The GUI fills the vtable in `gui_vtable_init` (`app/gui/gui-vtable.c:207-237`).
  2. **Abstract types defined in the core**:
     - `GimpDisplay` is a core `GimpObject` (`core/gimpdisplay.c:64`), subclassed by GUI `GimpDisplayImpl` (`display/gimpdisplay.c:126`).
     - `GimpProgress` is a GInterface (`core/gimpprogress.c:43`) implemented by `GimpDisplayShell` and others.
     - Also `GimpWaitable`, `GimpCancelable` and `GimpPickable`.
  3. **GObject signals** on Gimp, GimpImage ("flush", "selected-layers-changed"), GimpProjection ("update") and GimpContext, which the GUI subscribes to.
  4. **Previews**: `GimpViewable` produces `GimpTempBuf` previews in the core, and GUI `GimpViewRenderer` draws them with cairo.
- `app.c` and `main.c` use `#ifndef GIMP_CONSOLE_COMPILATION` to remove GUI calls in gimp-console. [C]

## 5. GTK's role vs GIMP's widget layer; actions, menus, shortcuts

**GTK3 supplies [C/I]:**
- Toplevels: `GimpWindow` extends `GtkApplicationWindow` (`widgets/gimpwindow.c:62`).
- Containers: `GimpDockbook` is a `GtkNotebook`, `GimpDock` and `GimpDockColumns` are `GtkBox`, `GimpDockable` is a `GtkBin`.
- Tree views (`GimpContainerTreeView` wraps `GtkTreeView`).
- Event delivery and input devices (GdkDevice, used by `app/widgets/gimpdevices.c` and `display/gimpmotionbuffer.c`).
- CSS theming (`app/gui/themes.c:103-108` installs a `GtkCssProvider`; the Default theme has dark/gray/light CSS).
- File chooser, DnD and clipboard, monitors and HiDPI scale.

**libgimpwidgets** (58 GObject types) holds reusable widgets for both the app and plug-ins: color areas and buttons, spin scales, size entries, `GimpZoomModel`, `GimpColorDisplayStack`, `GimpColorSelector`, and the monitor color-profile lookup `gimp_widget_get_color_transform` (`libgimpwidgets/gimpwidgetsutils.c:907`). [C]

**app/widgets** (204 types) holds app-specific widgets: docking, container views, view renderers, the action and UI-manager system, the dialog factory, session info, toolbox and overlays. [C]

**Actions [C]**
- `GimpAction` is a GInterface (`widgets/gimpaction.c:109`). It is implemented by `GimpActionImpl`, `GimpToggleAction`, `GimpRadioAction`, `GimpEnumAction`, `GimpDoubleAction` and `GimpProcedureAction`, each of which also implements `G_TYPE_ACTION`.
- `GimpActionGroup` implements `G_TYPE_ACTION_GROUP`.
- Groups are registered from `app/actions/actions.c` (46 entries in `action_groups[]`). Handlers live in `*-actions.c` and `*-commands.c`.
- `GimpUIManager` (`widgets/gimpuimanager.c`):
  - loads `menus/*.ui` through **GtkBuilder** into `GMenuModel`, wrapped by `GimpMenuModel` (`:508-554`);
  - adds actions to the GtkApplication action map (`:1194`);
  - sets accelerators with `gtk_application_set_accels_for_action` (`:1246`).
- `GimpMenu` and `GimpMenuBar` subclass `GtkMenu` and `GtkMenuBar`.

**Shortcuts [C].** The `shortcutsrc` file is written and parsed by `app/menus/shortcuts-rc.c` and controlled by `menus.c:438-501`. The legacy `menurc` `(gtk_accel_path …)` format is migrated in `core/gimp-user-install.c:673`. `gimp_action_set_accels` is the only sanctioned path (`gimpaction.c:550-575`). Plug-in procedures and GEGL filters become actions: there are 120 `gegl:` filter entries in `filters-actions.c`, and `actions/gimpgeglprocedure.c` wraps GEGL ops as procedures.

## 6. GEGL and babl: responsibilities and GIMP's configuration

**GeglBuffer [C]**
- Sparse, tiled, typed by a babl format.
- Default tile size is **128×128** (`gegl:gegl/buffer/gegl-buffer-config.c:145-158`, `gegl/gegl-config.c:220`). GIMP does not override it.
- A buffer is a `GeglTileStorage` (a handler chain) over a backend (`gegl-tile-storage.c:66-76`).
  - The chain is **cache → zoom → empty**.
  - `GeglTileHandlerZoom` builds **mipmap levels** by 2×2 downscale (`gegl-tile-handler-zoom.c:44-140`).
  - The empty handler supplies shared empty tiles.
- Backends: **RAM**, **file** and **swap** (`gegl-buffer.c:535-579`). The swap backend uses a writer thread, a gap-tree allocator and compression (`gegl-tile-backend-swap.c:156-339`), with codecs `gegl-compression-{nop,rle,zlib}.c`.
- **Global LRU tile cache** (`gegl-tile-handler-cache.c:90-94`, trim at `:513`, "wash" of 20% least-recently-used tiles at `:387`).
- **Copy-on-write tile cloning**: `gegl_tile_dup` and `n_clones` (`gegl-tile.c:119`), and the fast tile-copy path in `gegl_buffer_copy` (`gegl-buffer-access.c:2375-2548`).
- Scaled reads: `gegl_buffer_get(scale<1)` halves the scale while it is ≤0.5 and picks that mipmap level, then applies a NEAREST, BOX or BILINEAR filter (`gegl-buffer-access.c` `_gegl_buffer_get_unlocked`, lines around 2095-2160).
- Format conversion happens on get/set through babl fishes (17 babl calls in `gegl-buffer-access.c`).

**Graphs and operations [C]**
- `GeglNode` and pads (`gegl/graph/`).
- Evaluation via `GeglProcessor` and the eval manager (`gegl/process/`).
- Operation base classes: point filter/composer/composer3, area filter, meta, source, sink (`gegl/operation/`).
- Ops are GModules loaded at init (303 op sources in `gegl:operations/`).
- **Threading**: ops split their ROI with `gegl_parallel_distribute_area` (`gegl-operation-point-filter.c:290`, `-filter.c:202`, `-composer.c:186`; pool in `gegl-parallel.c`). The `threads` property defaults to the number of CPUs, capped by `GEGL_MAX_THREADS` = 64 (`gegl-config.h:59`). `chunk-size` defaults to 1M pixels.
- OpenCL is optional (`gegl/opencl/`).

**babl [C]**
- Models, types and formats (`babl-format.c`).
- **Fishes** are conversion objects: memcpy, simple, path and reference (`babl-fish.c:198-360`).
  - Path fishes search chains of at most 8 conversions within an error tolerance `BABL_TOLERANCE` = 0.0000047 (`babl-fish-path.c:27-29,779`).
  - The reference fish goes through double precision.
  - Chosen paths are cached on disk in `~/.cache/babl/babl-fishes` (`babl-cache.c:109,240,301`).
- **Spaces**: RGB matrix plus TRC, built in (sRGB, Rec2020, ProPhoto, Adobish, …) or **from ICC** (`babl-icc.c:960`).
  - TRC kinds: linear, gamma, sRGB, LUT (`base/babl-trc.h:29`).
  - CMYK ICC goes through lcms2 when babl is built with it (`babl-icc.c:1022-1036`).
  - Encodings carry the TRC in the name: `"RGBA"` is linear, `"R'G'B'A"` uses the space's TRC, `"R~G~B~A"` uses the perceptual (sRGB) TRC (`base/model-rgb.c:502`).
  - Indexed images use palette formats (`babl_new_palette_with_space`, `gimp:app/core/gimpimage-colormap.c:160`).

**How GIMP configures GEGL [C]** (`gimp:app/gegl/gimp-gegl.c:53-100`)
- Pushes swap path, swap compression (default "fast"), `tile-cache-size`, `threads` (= `num-processors`) and `use-opencl` into `gegl_config()`, and keeps them live through notify handlers.
- Defaults come from `app/config/gimpgeglconfig.c:118-157`:
  - tile cache defaults to **half of physical RAM**, capped at `GIMP_MAX_MEM_PROCESS`;
  - threads default to the CPU count;
  - OpenCL is off.
- Then it calls `gimp_parallel_init`, `gimp_babl_init` (registers component formats such as "R u8") and `gimp_operations_init` (56 type registrations, including layer modes; `app/operations/gimp-operations.c`).
- `gimp_babl_init_fishes` pre-creates about 30 common fishes during restore (`gimp-babl.c:124`).

## 7. Image representation and pixel storage

**Class tree [C]** (from G_DEFINE parents)
- `GObject → GimpObject → GimpViewable → GimpFilter → GimpItem → GimpDrawable(abstract)`.
- Under `GimpDrawable`:
  - **`GimpLayer`** → `GimpGroupLayer`, `GimpTextLayer`, `GimpVectorLayer`, `GimpLinkLayer`;
  - **`GimpChannel`** → `GimpLayerMask`, `GimpSelection`.
- `GimpImage` derives from `GimpViewable`.
- `GimpFilter` is a viewable that owns a lazily built **`GeglNode`** (`gimpfilter.c` `GimpFilterPrivate{node, active, is_last_node, applicator}`).

**Pixels [C].** `GimpDrawablePrivate` (`core/gimpdrawable-private.h`) holds:
- **one `GeglBuffer *buffer`** per drawable, plus a `shadow` buffer for filters;
- `source_node`, `buffer_source_node` and `mode_node`;
- a **`filter_stack`** (`GimpContainer` of `GimpDrawableFilter`, the non-destructive effects);
- floating-selection nodes, and the paint buffer and regions.

Group layers also have a buffer: it is their projection's buffer (see §8).

**GimpImage [C]** (`core/gimpimage-private.h`) holds:
- width, height, resolution;
- `base_type` (RGB, GRAY or INDEXED), **`precision`**, `color_profile`, `layer_space` (a babl space), simulation profile, cached transforms;
- **`projection` + `graph`**;
- three **`GimpItemTree`s** (layers, channels, paths);
- `selection_mask`, `floating_sel`;
- `undo_stack` and `redo_stack`, guides, grid, sample points, symmetries, parasites, metadata, dirty counters, and the load/save/export procedures.

`gimpimage.c` alone is 6.5k lines, and there are 28 `gimpimage-*.c` helper files.

**Precision [C].** `GimpPrecision` (`libgimpbase/gimpbaseenums.h:904-921`) has 18 values: {u8, u16, u32, half, float, double} × {linear, non-linear, perceptual}.
- `gimp_babl_format(base_type, precision, alpha, space)` (`app/gegl/gimp-babl.c:843`) maps these to babl encodings such as `"R'G'B'A u16"` and `"R~G~B~ u8"`, using `babl_format_with_space`.
- Masks use `"Y <type>"` (`gimp_babl_mask_format`, `:1091`). The selection uses `gimp_image_get_mask_format` (`gimpimage.c:2362`).
- The projection format is image precision with alpha; indexed is projected as RGB (`gimp_image_get_proj_format`).

## 8. Layers and groups

- **`GimpItemTree`** (`core/gimpitemtree.c`) owns a root `container`, the selected items and a name hash. It does insert-position resolution, add, remove, reorder and unique naming across nested containers via `gimp_viewable_get_children`. [C]
- The image creates its trees as (`gimpimage.c:818-826`) [C]:
  - layers → `GimpLayerStack`/`GimpLayer`
  - channels → `GimpDrawableStack`/`GimpChannel`
  - paths → `GimpItemStack`/`GimpPath`
- Container chain: `GimpLayerStack → GimpDrawableStack → GimpItemStack → GimpFilterStack → GimpList → GimpContainer` (a GListModel). [C]
- `GimpDrawableStack` re-emits child "update" signals (`gimpdrawablestack.c:77,111`).

## 9. Compositing, opacity, blend modes

**Per-layer graph [C]**
- `gimp_drawable_get_node` (`gimpdrawable.c:516`) creates `input → mode_node ("gimp:normal") → output`.
- `gimp_drawable_get_source_node` (`:1773`) builds `class source (buffer source) → filter_stack graph (NDE effects) → output`.
- `gimp_layer_get_node` (`gimplayer.c:794`) adds:
  - source → `gegl:translate` (layer offset) → mode_node **"aux"**;
  - mask source → `gegl:translate` → mode_node **"aux2"**. When "show mask" is on, the mask goes to aux instead.
- `gimp_layer_update_mode_node` (`:669`) calls `gimp_gegl_mode_node_set_mode` (`gegl/gimp-gegl-nodes.c:170`). That function swaps the node's operation to the mode's op and sets `opacity`, `blend-space`, `composite-space` and `composite-mode`, resolving AUTO from the mode's metadata.

**Image graph [C]** (`gimp_image_get_graph`, `gimpimage.c:1708`)
- layers stack graph → `gimp:mask-components` (per-RGBA-channel visibility) → channels stack graph → output.
- Visible saved channels composite as colored overlays (`gegl:color` + `gegl:opacity` with the channel as aux, then the mode node; `gimpchannel.c` `get_node`).

**Layer modes [C]**
- `GimpLayerMode` has 65 modes plus a separator. 22 of them are `*_LEGACY`; there are also LCH, luma and Porter-Duff-like modes (erase, merge, split, replace, overwrite, anti-erase, pass-through) (`app/operations/operations-enums.h:56-140`).
- The metadata table `layer_mode_infos[]` (`layer-modes/gimp-layer-modes.c:55`) records the op name, flags (LEGACY, *_IMMUTABLE, TRIVIAL), allowed contexts (layer, group, paint, filter), and default composite mode and space.
- **`GimpOperationLayerMode`** is a `GeglOperationPointComposer3` (`gimpoperationlayermode.c:128`) with inputs input = backdrop, aux = layer, aux2 = mask (`"Y float"`).
  - `prepare` (`:304`) picks the blend function.
  - If the input is empty, it acts as the bottom ("last") node and uses UNION or a shortcut (`:328-358`).
  - It processes in float, converting between linear, non-linear, perceptual and CIE Lab through cached babl fishes (`:936-1004`).
  - Separate code files implement blend and composite, with SSE2/SSE4 variants for normal mode.
- Legacy modes are separate ops in `layer-modes-legacy/` (perceptual-space, old math). Opacity is a property of the mode op, not a separate node.

**Projection [C]** (`core/gimpprojection.c`)
- A `GeglBuffer` sized to the bounding box with **`GimpTileHandlerValidate`** attached (`:582-604`).
  - The handler keeps a cairo dirty region.
  - On `GEGL_TILE_GET` at **z==0** it renders dirty parts of the tile by `gegl_node_blit(graph, …)` (`gimp:app/gegl/gimptilehandlervalidate.c:241,412-422`). Rendering is **lazy and pull-based**.
- Change flow:
  1. `GimpDrawable` "update" → drawable stack "update" → `gimp_image_invalidate` (`gimpimage.c:847,3909`) → `gimp_projectable_invalidate`.
  2. The projection adds the area, aligned to 32×32 (`:626-643`).
  3. `gimp_image_flush` (`:4276`) → projection flush → **idle chunk renderer** (`:686-866`) at `GIMP_PRIORITY_PROJECTION_IDLE`.
  4. The chunk renderer uses `GimpChunkIterator` (adaptive chunk area, 1/15 s target interval, `gimpchunkiterator.c:38-54`) with a **priority rect** set by the display to the visible viewport (`display/gimpdisplayshell.c:2158`).
  5. Each chunk is validated, then the projection emits "update" → `GimpDisplay` (`display/gimpdisplay-handlers.c:60`).
- Rendering is driven from the GTK main loop; parallelism lives inside the GEGL ops. [C for code; I that no other render thread exists for the projection]

## 16. XCF native format

**File layout [C]** (`app/xcf/xcf-save.c:307-480`, `xcf-load.c`)
- The tag `"gimp xcf file"` (version 0) or `"gimp xcf v%03d"`.
- width, height, base_type, then **precision** (newer versions).
- Image properties, then a 0-terminated **layer offset table**, then a **channel offset table** (the selection is saved as a channel).
- Offsets are 32-bit, or 64-bit from v11.

**Properties [C].** Properties are a typed TLV list (`PROP_*`, 59 ids in `xcf-private.h`). Examples: `PROP_MODE` 7, `PROP_COMPRESSION` 17, `PROP_PARASITES` 21, `PROP_GROUP_ITEM` 29, `PROP_ITEM_PATH` 30, `PROP_COMPOSITE_MODE` 35, `PROP_BLEND_SPACE` 37, `PROP_FILTER_*` 44-46, `PROP_VECTOR_LAYER` 47, `PROP_LINK_LAYER` 48.

**Layer record [C]** (`xcf_save_layer`, `:2023`):
- width, height, type, name, properties;
- **hierarchy** offset;
- mask offset (the mask is saved as a channel);
- effect and effect-mask offsets (non-destructive filters, saved since v22).

**Hierarchy and levels [C]** (`xcf_save_buffer`, `:2569`):
- The hierarchy stores width, height, bpp and a level offset table.
- **Only level 0 holds data**; the other levels are dummy empty levels kept for compatibility (`:2610-2640`).
- A level is a tile offset table of **64×64 tiles** (`XCF_TILE_WIDTH/HEIGHT`, `xcf-private.h:21`).
- Compression is **RLE** (`xcf_save_tile_rle`, `:3035`) or **zlib** (`:3153`; v8+).
- The tile data limit is 1.5× the raw size.
- Tiles are compressed in parallel batches of 128 (`xcf_save_tile_parallel`).

**Versioning [C].** Loaders exist for versions 0-26 (`xcf.c:69-97`). `gimp_image_get_xcf_version` (`core/gimpimage.c:2849`) chooses the **lowest version that can hold the image's features** and records the reasons:

| version | feature |
|---|---|
| 2 | legacy-era modes |
| 3 | groups |
| 7 / 12 | high bit depth / its encoding |
| 8 | zlib compression |
| 9, 10 | new modes |
| 11 | files over 4 GB |
| 13 | group masks |
| 14 | multi-select |
| 17 | locks |
| 18 | path features |
| 19 | text font format |
| 22 | layer effects |
| 23 | perceptual blend space |
| 24 | vector layers |
| 25 | link layers |
| 26 | channel effects |

**Workspace presets: absent [C].** There is exactly one live layout file (sessionrc) plus a reset. No named-layout or preset code exists; a grep for "workspace" in app/ shows only unrelated hits. Tool presets (`GimpToolPreset`) exist, but they cover tool options, not layout.

## 20. Observations

**Abstractions that exist mainly because GIMP is mature and feature-rich**
1. **PDB plus out-of-process plug-ins.** This covers 786 generated internal procedures, a wire protocol with its own tile transport, pluginrc caching, interpreter databases, GI typelibs, Script-Fu and temporary procedures. It buys crash isolation, multi-language scripting and a stable public API, at a large complexity cost. Even XCF and file dispatch go through it.
2. **18 precisions × babl spaces, plus per-layer blend space, composite space and composite mode.** On top of that come 22 legacy layer modes and the legacy-op directory, kept for old XCF fidelity, and XCF loaders for 27 versions with minimum-version feature negotiation.
3. **Console/GUI dual build.** `GimpCoreApp`, the `GimpGui` vtable, and core-defined `GimpDisplay` and `GimpProgress` exist so batch processing works without GTK.
4. **Session and docking machinery.** This includes dialog-factory registries (89 entries), session-info serialization, single and multi-window strategies, hide-docks, and dockable tab styles.
5. **Action system.** GimpAction* wraps GAction for enum, double and procedure actions, plus action history and search. Menus are XSL-generated `.ui` files.
6. **Data factories** with many legacy formats (GBR, GIH, VBR, ABR, PSP brushes; Photoshop and GIMP gradients and palettes), tags, extensions and modules.
7. **Floating selection, quick mask and parasites.** These are historical concepts woven into drawable and image code: `fs_filter`, `fs_applicator`, `floating_sel`.
8. **Newer item kinds.** Text, vector and link layers (`GimpRasterizable`) and non-destructive filter stacks, each adding undo types and XCF properties.

**Foundational decisions that look hard to change**
- **C plus GObject everywhere.** Signals are the primary coupling between core and GUI, and between items, containers, image and projection.
- **GEGL as the pixel model.** There is one GeglBuffer per drawable, a projection that is a GEGL buffer validated lazily by a custom tile handler, and a layer tree compiled into a **linear GEGL node chain** with group sub-projections. Blend modes are GEGL ops. Swapping engines would touch nearly everything.
- **GTK3.** About 600 GUI files include gtk.h, and widgets subclass GTK containers directly (dock = GtkBox, dockbook = GtkNotebook, shell = GtkEventBox). The project still requires GTK 3.24.
- **The PDB and protocol as a compatibility surface**, versioned with `GIMP_PROTOCOL_VERSION`, and XCF as a long-lived format.
- **Main-loop-driven rendering.** The projection renders in idle callbacks on the GTK main thread, with parallelism inside GEGL ops. The display copies projection pixels into a cairo surface per shell.

**Implications for a simpler WPF/SkiaSharp app** [I]
- These GIMP ideas transfer cheaply:
  - a core that never references the UI (interfaces plus events);
  - a tiled, copy-on-write layer buffer;
  - a cached composite with dirty-rect invalidation and a priority viewport;
  - view rotation, flip and zoom as a pure view matrix, with pan done by shifting a cached bitmap;
  - mipmaps for zoomed-out display;
  - undo as region snapshots grouped per action, with a memory cap;
  - a native format of tiles plus a property list with explicit versioning.
- These are the parts to drop or defer: PDB and out-of-process plug-ins, multiple precisions and legacy modes, per-layer color spaces, floating selections, console mode, modules, and full session docking. A single fixed layout, or a few named layout presets, would replace sessionrc. Presets are something GIMP itself lacks.

## 21. Unknowns and limits of this study
- I did not trace the full `GimpPaintCore` and `GimpApplicator` path. It is the painting agent's scope. I only confirmed that the applicator builds a small graph of `gimp:normal`, `gegl:buffer-source`, `gegl:translate` and `gimp:mask-components` nodes (`app/gegl/gimpapplicator.c:131-187`).
- Whether any other projection rendering happens off the main thread (for example async previews) beyond GEGL's internal thread pool. I believe it does not, but this is unverified [I].
- I did not determine exactly when `GimpColorTransform` uses babl versus lcms2. That depends on `gimp_color_profile_get_format` succeeding.
- The exact XCF channel/effect offset-table layout for v26 was not fully read.
- The "about 54 group / about 60 primitive" undo-type counts are approximate grep counts.
- The GEGL standalone default tile cache is derived from available memory (`gegl-config.c:325-345`), but GIMP overrides it, so the effective value is GIMP's setting.
